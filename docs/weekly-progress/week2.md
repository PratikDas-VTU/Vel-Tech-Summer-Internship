# Week 2: Vulnerability Research & Security Reporting

## Objectives
- Understand enterprise vulnerability management workflows.
- Learn how to review and standardise technical security assessment reports.
- Map publicly disclosed vulnerabilities to deployed software versions.

## Tasks Completed
### Security Report Review
- Reviewed and formatted **22 Web Application VAPT (Vulnerability Assessment and Penetration Testing) reports**.
- Focused on identifying formatting inconsistencies, verifying technical findings, and improving overall document structure and readability.

### Vulnerability Research & Software Analysis
Conducted a software component inventory across four internal application environments (MMI, Msigma, VPN, ePramaan).
- Identified outdated libraries and components (e.g., Angular, Bootstrap, jQuery, Chart.js).
- Researched the latest stable releases from official vendor sources.
- Queried the National Vulnerability Database (NVD) to identify publicly disclosed vulnerabilities (CVEs) affecting the deployed versions.

### Excel-Based Tracking
- Created a structured, four-sheet Excel workbook to document the vulnerability research findings.
- Mapped Component Names, Current Versions, Latest Versions, CVE Identifiers, and Severity Classifications to facilitate remediation efforts.

## Learning Outcomes
- Recognized the critical importance of accurate, standardized documentation in cybersecurity reporting.
- Gained practical exposure to CVE analysis, CVSS severity classification, and software version management.
- Identified that manual review of complex security reports is time-consuming and prone to human error, establishing the motivation for the automation project in Weeks 3 and 4.
